# 004 - Real Sleep Real Testprotokoll

## Zweck

Diese Datei beschreibt das naechste Forschungsprotokoll.

Es geht um die Frage:

```text
Aendert eine entkoppelte Sleep-Phase,
was MINI_DIO im gleichen realen Weltkontakt danach wieder erkennt?
```

Das ist keine Behauptung. Es ist eine kontrollierte Pruefung.

## Ablauf

```text
1. frische Memory
2. Real Run A mit Welt X
3. Memory A speichern
4. Sleep Phase aus Memory A
5. Memory nach Sleep getrennt speichern
6. Real Run B mit derselben Welt X
7. Vergleich A gegen B
```

## Was Geprueft Wird

Nicht geprueft wird Handlung.

Geprueft wird:

- Symbolwiederkehr,
- MCM-Episodenrollen,
- rekopplungstragende Rollen,
- offene/ungeklaerte Rollen,
- Nachhall,
- Feldzeit,
- Topologie,
- Bedeutungsinseln,
- ob alte Muster gefestigt erscheinen,
- ob neue Offline-Bindungen spaeter wieder auftauchen.

## Trennung Der Dateien

Die Testkette muss getrennte Speicher schreiben:

```text
memory_A_real_run.json
memory_A_after_sleep.json
memory_B_real_run_after_sleep.json
```

Damit darf nicht vermischt werden:

```text
was aus realem Weltkontakt entstand
was in der Sleep-Phase aktiv wurde
was im zweiten realen Kontakt anders erscheint
```

## Auswertung

Der Vergleich A gegen B soll mindestens messen:

- gleiche `dio_*`-Syntax,
- neue `dio_*`-Syntax,
- wiederkehrende MCM-Episodenrollen,
- neu entstandene MCM-Episodenrollen,
- Veraenderung der Rollenqualitaet,
- Veraenderung von Nachhall und Feldzeit,
- offene Rollen, die nach Sleep staerker oder schwächer auftreten.

## Grenze

Wenn sich Run B veraendert, ist das noch kein Beweis, dass Sleep Bedeutung erzeugt hat.

Es waere zuerst ein Hinweis auf:

```text
Sleep-Phase kann Memory-/Feldnaehe vor dem zweiten Weltkontakt veraendern.
```

Erst mehrere Wiederholungen mit gleicher und anderer Welt koennen zeigen, ob daraus stabile Musterfestigung oder neue Bindung entsteht.
